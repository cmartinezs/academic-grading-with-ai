# ADR-0010 — Discovery propone instancias; no redefine el core

- Estado: Propuesto
- Fecha: 2026-08-01

## Contexto

Un LLM puede ayudar a interpretar briefs, rúbricas y convenciones de un docente. El diseño
anterior permitía que discovery propusiera `schemas` y `patrones de parsing`, lo que
traslada contratos del core a una salida no determinista y puede introducir código o
semántica no revisada.

## Decisión

La capa `discovery/` es opcional y no determinista. Puede proponer únicamente instancias
compatibles con contratos existentes, por ejemplo:

- `section-config` candidata;
- `grade-policy` candidata usando operadores registrados;
- mapping de columnas/campos para adapters existentes;
- forms y metadata;
- advertencias y preguntas pendientes.

No puede:

- crear o modificar schemas del core;
- crear operadores;
- emitir código ejecutable;
- definir expresiones libres;
- modificar parsers;
- aprobar resultados;
- publicar;
- enviar emails.

Flujo obligatorio:

```text
proposal
→ schema validation
→ deterministic semantic validation
→ diff against current accepted config
→ human review
→ explicit acceptance
→ versioned deterministic instance
```

Se registra provenance de modelo, prompt, inputs, fecha y reviewer. Una vez aceptada la
instancia, el pipeline determinista no vuelve a invocar al LLM.

## Alternativas consideradas

### LLM genera schemas y parsers

Rechazada: rompe gobernanza y determinismo.

### Sin discovery

Viable, pero pierde asistencia de onboarding.

### Discovery limitado a instancias

Aceptada.

## Consecuencias

- C7 se implementa después de estabilizar schemas y grade policy.
- Nuevos casos fuera del perfil V1 siguen el proceso formal de extension points/ADR.
- La aprobación humana no reemplaza validaciones automáticas.
- Los datos enviados al proveedor LLM deben respetar la política de PII y consentimiento.
