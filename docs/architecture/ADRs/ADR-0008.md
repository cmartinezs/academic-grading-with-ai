# ADR-0008 — Portal: fragmentos por estudiante + access codes en hosting estático

- Estado: Propuesto
- Fecha: 2026-08-01

## Contexto

El portal se publicará en hosting estático. Sin backend, no hay limitación de intentos
de códigos; por lo tanto la seguridad depende del diseño de datos y de los códigos.

## Decisión

- **Fragmentos por estudiante**: un archivo HTML/JSON por estudiante; el directorio de
  salida nunca contiene un dataset global servible.
- **Access codes PBKDF2(250k)**: el código desbloquea solo el fragmento propio.
- Códigos/enlaces entregados por el pipeline de email.
- `publish` exige flag explícito y `PORTAL_BASE_URL` https; sin hosting configurado el
  portal queda en preview local.
- Retención: últimas N builds (default 5); `revoke`/`purge`.
- Comparativas permitidas: solo agregados de curso; prohibido ranking individual.

## Consecuencias

- Un código comprometido expone un solo estudiante.
- Riesgo residual de brute-force documentado en la hosting checklist.
- El estándar define el contrato de build; el hosting provee TLS/control de acceso.
