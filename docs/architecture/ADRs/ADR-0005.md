# ADR-0005 — Node.js opcional detrás de contratos de publishers

- Estado: Propuesto
- Fecha: 2026-08-01

## Contexto

El core actual es Python. El repositorio de referencia implementa portal y email en
Node.js. Reescribirlos antes de validar sus contratos agrega costo; incorporar Node dentro
del core agrega acoplamiento.

## Decisión

Node.js se permite únicamente en publishers/adapters operacionales claramente aislados:

- portal;
- email.

Reglas:

- el core Python no importa ni ejecuta módulos Node internamente;
- el boundary es un contrato versionado de archivos/CLI;
- Node consume un Publication Snapshot aprobado o una proyección validada;
- Node no parsea Markdown, no aplica grade policy y no modifica el snapshot;
- dependencias y runtime se pinnean;
- ausencia de Node no rompe parsing, cálculo, snapshots ni proyecciones Python;
- cada wrapper valida runtime y versión antes de ejecutar;
- no se mantiene una segunda implementación Python "provisoria" del mismo publisher.

## Alternativas consideradas

### Reescribir todo en Python

Postergada: puede evaluarse cuando los contratos estén estabilizados y exista beneficio
medible.

### Incorporar Node al core

Rechazada: mezcla runtimes en lógica académica determinista.

### Node opcional detrás de contratos

Aceptada: permite reutilizar código probado sin convertirlo en dependencia del core.

## Consecuencias

- Existen dos toolchains, pero con fronteras explícitas.
- Los tests de contrato deben ejecutarse contra fixtures compartidos.
- Un cambio de implementación no afecta consumidores mientras preserve el contrato.
- El portal/email pueden evolucionar o reescribirse sin alterar el grade engine.
