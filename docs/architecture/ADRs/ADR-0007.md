# ADR-0007 — Clasificación de datos, identidad opaca y PII fuera de Git

- Estado: Aprobado
- Fecha: 2026-08-01
- Fecha de aprobación: 2026-08-01

## Contexto

El workspace maneja roster, RUT, emails, entregas, feedback y notas. La política anterior
indicaba minimización, pero no resolvía que `students.json` y otros artefactos pudieran
vivir dentro del repositorio. El código actual también puede usar RUT o slug de nombre como
`studentId`, lo que no constituye una identidad técnica segura.

## Decisión

### Identidad

- El core usa `studentId` opaco, estable y no derivado de PII.
- RUT, email, AVA user y otros identificadores externos viven en un mapping privado.
- Un hash simple de RUT no se considera anonimización.

### Almacenamiento

Se separan físicamente:

- código versionado;
- datos privados de runtime;
- Publication Snapshots;
- estado operacional;
- artefactos publicables.

PII, submissions, previews, snapshots reales, logs, ledgers y secretos no se versionan.
El pipeline valida que los datos reales estén en una raíz privada/ignorada antes de
procesarlos.

### Minimización

Cada proyección declara audiencia y allow-list de campos. Un opt-in de PII requiere:

- propósito;
- audiencia;
- justificación;
- retención;
- revisión explícita.

### Logging

Solo se registran IDs opacos, estados, hashes y referencias a `publicationId`. Se prohíben
cuerpos, feedback, RUT completo, emails completos y secrets.

## Alternativas consideradas

### Repositorio privado como único control

Rechazada: no elimina clones, history, errores de push ni exposición a herramientas.

### PII en Git con cifrado manual

Rechazada para V1: complejidad operacional y riesgo de mal uso.

### Datos fuera de Git

Aceptada: frontera simple y verificable.

## Consecuencias

- Se requiere migrar workspaces existentes con datos reales.
- Los fixtures de tests deben ser sintéticos.
- Portal, email y BI reciben vistas mínimas distintas.
- Los scripts que hoy usan RUT como clave requieren adaptación.
- La política detallada vive en `05-security-and-data-boundaries.md`.
